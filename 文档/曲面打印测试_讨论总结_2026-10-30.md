# 曲面打印测试｜阶段讨论总结111

- 整理日期：2026-10-30
- 用途：纳入“曲面打印测试”项目，作为后续测试、问题追踪和服务器归档的讨论基线。
- 整理范围：本对话中的需求、选型讨论、工程风险及测试建议。
- 证据边界：本文件是对话汇总，未在本轮重新检查现机、执行运动、测量精度或验证电气接线。**方案建议、资料描述、用户陈述与实测通过必须分开记录。**

## 一、项目目标与当前优先级

项目不只是完成一次曲面打印，而是建立可重复的测试流程，将有价值的问题及其解决过程沉淀为内部知识。

需要保留的内容包括：

1. 打印过程出现了什么问题。
2. 问题出现的时间、位置、姿态和运行条件。
3. 问题前后的一段运动、温度、挤出与视频数据。
4. 原因假设、修改措施，以及同条件复测结果。
5. 能够复用的方案、参数和操作文档，后续存入内部服务器。

**当前明确优先解决：基础功能与打印质量。**

建议顺序：

> 基本安全前提 → 基础功能可重复 → 平面打印质量基线 → 曲面及五轴打印质量 → 长期稳定性与多台一致性。

现阶段不必同时铺开全部寿命、运输和认证测试；但温控、接地、运动干涉、异常停止等基本安全问题不能后置。

## 二、基础功能测试

目标：每次都能正确开始、执行和结束，而不是偶然成功一次。

| 项目 | 测试重点 | 建议记录 |
|---|---|---|
| 回零与坐标建立 | XYZ及U/V的顺序、方向、限位与重复性 | 回零过程、位置测量、异常状态 |
| 单轴及联动运动 | 全行程、换向、姿态切换、线束拉扯与机构干涉 | 指令、位置/姿态、视频 |
| 加热与冷却 | 到温、超调、稳态波动、测温及风扇控制 | 温度曲线、环境和目标温度 |
| 供料与挤出 | 进退料、连续供料、回抽、堵料或打滑 | 材料、温度、速度、异常现象 |
| 打印前准备 | 清洁、测量/调平、喷嘴间距建立是否可重复 | 流程版本、首层结果 |
| 暂停、恢复与取消 | 恢复位置、挤出状态、加热和使能状态 | 操作时间、状态变化、结果 |
| 异常保护 | 传感器、温控、通信或电机异常后的整机行为 | 报警、停机过程、残余风险 |

通过标准应在测试前定义，结合目标层高、结构和测量能力制定。**暂不把未经测量的通用数字写成整机合格标准。**

## 三、打印质量验证路线

### 3.1 固定基准条件

建立一套可追溯的基准配置：

- 机器编号、机构/电气版本。
- 主板、固件、配置和切片版本。
- 材料类型与批次、喷嘴规格。
- 层高、线宽、温度、速度、加速度、回抽等参数。
- 打印面状态、准备流程与环境条件。

每次试验只改变一个主要因素，避免多个改动同时发生而无法归因。

### 3.2 由简单到复杂

| 阶段 | 建议试件 | 重点观察 |
|---|---|---|
| 平面首层 | 单层方片、网格 | 附着、线宽/厚度一致性、刮料、断线、堆积 |
| 平面质量基线 | 薄壁、尺寸件、拐角特征件 | 挤出一致性、尺寸、振纹、接缝、拐角堆料 |
| 简单曲面 | 曲面单线、曲面网格、薄壳 | 喷嘴间距、不同位置及姿态下的成形一致性 |
| 代表性五轴零件 | 实际目标零件 | 完整流程、复杂姿态、重复打印结果 |

曲面专项重点：

1. 不同姿态下，喷嘴相对工件的位置和间距是否正确。
2. 转轴换向、加减速和大姿态变化处是否缺料、堆料或碰撞。
3. 同一目标从不同方向接近时是否存在差异。
4. 冷机、热机、重新回零后，结果能否复现。

评价尽量包含测量和原始数据，不只保留“看起来不错”的照片。

## 四、运动反馈采集需求与边界

### 4.1 采集目标

希望捕获：

- 指令运动与电机实际运动之间的差异。
- 实际位置、速度、位置误差、接收脉冲和报警状态。
- 可获取时的电流、电压、驱动器温度等辅助诊断信息。
- 异常前后一段时间的数据，用于与温度、挤出、视频和实物缺陷对齐。

### 4.2 关键边界

- 闭环驱动器内部能够纠偏，不等于所有反馈都能通过接口读出。
- 电机轴编码器不等于负载侧位置，更不等于喷嘴相对工件的真实轨迹。
- 自动定时回传不等于多轴同步采样。
- 内部控制环频率不等于对外采集频率。
- 采集程序收到数据的时间，不必然是传感器采样时间。
- 需要处理时间对齐、延迟、丢包和通信负载。
- 逻辑轴数量不等于电机数量；全机采集规模应按实际电机节点计算。

**暂不把全机闭环改造作为开始基础功能和打印质量测试的前置条件。**先利用现有日志、视频、温度和实物测量建立基线，再增加单轴反馈。

### 4.3 建议的“双通路”

```text
控制通路：
Klipper → 打印机主板 → STEP/DIR/EN → 闭环驱动器 → 电机

采集通路：
闭环驱动器 → CAN或TTL等接口 → 适配器 → 独立采集程序 → 日志/服务器
```

“双通路”是系统分工，不是两套编码器，也不是Klipper已经形成了整机位置闭环。

采集程序初期只做观测，不与Klipper同时发送位置、速度等运动命令。

## 五、张大头与MKS选型讨论

### 5.1 当前推荐

优先验证：**张大头X42S_V2.0/B系列，PLC脉冲＋CAN配置，配匹配电机的完整套装，先一套。**

这只是当前需求匹配度排序，不是已经证明其精度、噪声、温升或打印质量优于MKS。

| 项目 | 张大头X42S系列 | MKS SERVO42D |
|---|---|---|
| 脉冲与通信并行 | 手册明确描述混合控制；仍需交付版本实测 | CR/SR模式说明存在集成疑点，需要确认脉冲模式下能否完整连续反馈 |
| 运动反馈 | 有位置、速度、误差等读取资料 | 同样有核心运动反馈接口 |
| 辅助诊断 | 手册列有相电流、电压、驱动温度等字段 | 当前讨论手册未见同等完整的实测字段；工作电流配置回读不能当成实测电流 |
| 定时回传 | 有相关命令 | V1.0.9也有 |
| 同配置价格与实测 | 尚未形成可比报价和对比结果 | 同左 |

MKS的关键待确认项：

> 在CR_CLOSE或CR_vFOC接收STEP/DIR运动时，位置、速度、接收脉冲、误差能否通过CAN查询及定时回传？

张大头的关键待确认项：

> 对应交付的硬件和固件，能否在持续脉冲运动期间稳定回传所需数据？多参数同时回传的稳定周期是多少？

两家均不能仅凭“支持毫秒级配置”就认定能够全轴同步、稳定、无丢包地高速采集。

### 5.2 “资料公开”与“全部开源”

张大头存在公开说明、通信资料及社区通信程序，但本次讨论没有核实到所选交付版本的完整官方固件源码、开源许可及完整硬件工程。

因此：

- 不把“能下载固件”写成“固件开源”。
- 不把“有社区读取程序”写成“厂家内部算法开源”。
- 当前优先要求协议完整、单位和反馈含义清楚、混合控制可验证。
- 如果将来需要改内部采样或时间戳，再重点评估固件开放程度。

## 六、Octopus MAX EZ接入与通信

### 6.1 PLC脉冲版与光耦版

讨论中据资料得到的接线方向：

- MAX EZ驱动相关STEP/DIR/EN经过5V电平处理。
- X42S手册描述PLC版与光耦版均支持3.3～24V脉冲输入。
- 光耦版仅支持共阳输入；不能只按电压判断驱动能力。
- 为降低初期接入复杂度，优先评估PLC脉冲版。
- 光耦版还要核对输入电流、最小脉宽及实际波形，不能直接宣称接上就可靠。

需要区分动力24V、信号5V、COM及GND，不能混接。

### 6.2 是否需要转接板

讨论中核对的MAX EZ V1.0原理图显示，M1～M7具有EN/STEP/DIR/GND引出接口。**实板版本、排针是否安装及所选通道仍需核查。**

建议：

1. 优先使用现成信号引出口及可靠线束。
2. 若必须从EZ插槽取信号，使用针脚和结构匹配的EZ引出板。
3. 不把普通A4988/StepStick转接板默认当作EZ兼容板。
4. 不把电机绕组四线输出口当作STEP/DIR信号接口。
5. 替换通道驱动时，需核对原驱动、Klipper使能极性、脉宽和相关配置，不能直接按原配置高速运行。

### 6.3 USB-CAN与主板桥接

已讨论两种方案：

| 方案 | 特点 |
|---|---|
| 主板保持原USB连接，另接USB-CAN采集 | 推荐用于初期验证，减少对现有打印控制的改动 |
| MAX EZ刷USB转CAN桥接固件 | 可评估共用主板的USB-CAN能力，但会改变主板连接配置，并增加调试耦合 |

普通CAN通信固件与USB转CAN桥接固件不是同一种配置。

无论哪种连接方式，都不代表Klipper自动认识张大头协议，仍需对应采集程序。桥接方案还需检查设备标识、CAN ID、波特率、带宽和复位后的恢复行为。

### 6.4 CAN速率与终端电阻

用户已表示购买USB-CAN适配器；具体型号和开关配置尚未确认。

基本检查：

- USB-CAN与电机的CAN通信速率一致。
- 总线物理两端各配置一只120Ω终端，跨接CAN-H/CAN-L。
- 检查适配器、电机是否已内置或启用终端，避免重复添加。
- 全部断电、包括USB供电断开后，双120Ω终端的总线通常测得约60Ω；该检查不能代替完整接线和通信验证。

### 6.5 现有电机的TTL/CAN身份尚未闭环

用户展示的板卡丝印为X42S_V2.0B，通信引脚标有R/A/H、T/B/L。

这些复用标记本身不能确认实际安装了哪种收发器。用户推测现有电机是TTL版本，另购的是CAN版本，**最终身份与交付配置仍待确认**。

待实施建议：

- 若确认现有板卡是TTL版，可先用匹配的USB-TTL设备验证读取和记录流程，不必等待CAN版才能开始。
- 先确认串口信号电平、引脚、波特率、协议及固件版本，不能使用24V或RS232电平直接接TTL信号。
- 初期先做静止只读验证，再做脉冲运动期间的并行读取。
- TTL验证通过不等于CAN链路验证通过；换接口后仍需验证组帧、速率、延迟和丢包。

本对话尚无TTL或CAN实际读取成功的测试证据。

## 七、线性霍尔＋长方形磁石用于U轴调平

### 7.1 当前评价

值得做低成本可行性试验，但优先定位为：

> **找回已标定的U轴参考姿态，而不是独立判断平台是否真正水平。**

线性霍尔测量磁场分量，不直接测距离或角度。“输出与磁场线性”不等于“输出与磁石距离线性”。

### 7.2 推荐验证思路

- 磁石安装在随U轴转动、具有有效力臂的位置。
- 霍尔安装在刚性参考支架上。
- 先用可靠外部测量建立正确姿态，再记录对应读数。
- 只在零位附近选用单调、未饱和的工作区间。
- 必须明确目标是相对喷嘴运动平面，还是相对重力水平。

需要关注：

- 磁化方向、敏感轴、间隙与安装公差。
- 热床加热后磁石、传感器和支架的漂移。
- 正反向接近产生的差异。
- 电机、加热器及供电变化对读数的影响。
- 其他运动或结构受力是否也改变测量间隙。

几何示例：有效力臂100 mm、零位附近，0.1°约对应0.175 mm高度变化，0.01°约对应17.5 μm。**这是几何换算，不是方案已达到的精度。**

建议先只采集，进行冷/热态漂移、已知角度标定、双向重复接近和外部复核；通过后再考虑自动修正。若要测全行程输出角度，另评估安装在输出侧的角度编码器。

状态：概念方案，尚无型号锁定、安装方案或实测结果。

## 八、热床、滑环与继电器的安全待办

用户曾提出的方案参数：

- 直径260 mm、220VAC/1000W硅橡胶加热板。
- “陶瓷限温125℃”，器件具体类型和动作方式待确认。
- 加热电流经过标称单路最大5A的导电滑环。
- 系统使用24V控制电源。

本次讨论应保留的风险判断：

1. 标称工作电流约1000/220＝4.55A。加热回路的两根导线上流过相同回路电流，不是各分一半。
2. 4.55A接近5A铭牌值，不能仅凭没有超过5A就判定适合工程定型；仍需确认连续额定条件、温升、绝缘、寿命和环境。
3. 多路滑环的总标称电流不能当作单路容量，也不能未经厂家允许直接并路扩容。
4. 125℃加热器限温不能自动保护允许温度更低的滑环或接插件。
5. 24V通过继电器不能变成220V；控制电源和加热动力电源是不同回路。
6. 继电器/SSR标注25A不代表任何环境、任何散热条件都能承载25A。
7. 金属旋转平台需要评估合格的保护接地通路，不能默认轴承可替代。
8. 应评估独立过温切断、过流及漏电保护、可靠散热和SSR失效情形。

状态：未完成工程验证，不能作为已批准的市电接线方案。后续危险故障验证需专业人员和安全工装实施。

## 九、问题台账与服务器归档

### 9.1 每条记录的最小字段

| 字段 | 内容 |
|---|---|
| 问题编号与状态 | 新发现、复现中、措施验证中、已关闭、重新打开 |
| 机器和版本 | 机器编号、硬件、固件、配置、切片版本 |
| 测试条件 | 材料、喷嘴、温度、速度、姿态、环境 |
| 问题现象 | 可观察描述，与预期的差异 |
| 触发位置和时间 | 任务、阶段、坐标/姿态、时间或事件编号 |
| 原始证据 | 日志、视频、温度、反馈数据、照片和量测 |
| 原因假设 | 区分推测与已验证原因 |
| 修改措施 | 改了什么、为什么改、对应版本 |
| 复测结论 | 测试条件、结果、是否满足标准 |
| 风险与适用范围 | 未解决问题、限制、可复用条件 |

建议异常数据保留事件前后一段时间，窗口长度依据采样率、问题持续时间和存储预算确定，不先把某个固定秒数写成通用要求。

### 9.2 记录原则

- 事实、推测和建议分开。
- 成功与失败样本都保留。
- 原始数据与处理结果分开，保留单位、时间基准和解析规则。
- 修改可追溯，复测尽量保持原条件。
- 不把“读取到了数字”当作“测量准确”，也不把“单次打印成功”当作“问题关闭”。

这些主题后续应按“明确问题 → 查验对应版本资料 → 设计测试 → 留存结果”的方式逐项补齐。
