# Klipper 接入契约（v1 已实现，默认关闭）

v0.3 已提供 `klipper/klippy/extras/rtcp.py`：在既有 G-code 坐标层和
`corexy_uv` 之间做自适应 XYZUV/E 细分，并复用 Klipper 运动队列。
适配层默认关闭，启动宏/结束宏、实机定时和打印质量仍需现场验收。
下面的安全门槛仍有效。Open5x 的具体审查结论见 `open5x-adaptation.md`。

## 分层

```text
Rhino / Open5x 导出适配
    → 模型坐标 XYZ + 明确语义的 UV + E/F/工艺事件
    → 工作配准 + RTCP 几何 + 有误差界的细分
    → 统一 XYZUV/E 时间规划 / 前瞻 / 限速 / 挤出策略
    → CoreXY XY + 四 Z + UV + E
```

Klipper v1 接入已经完成。不能把离线 JSON 结果绕过该适配层直接接到串口打印。
适配层位于树莓派 Klipper 主机侧，共享现有运动队列，不另建独立定时发步进进程。
但“主机插件”不保证无需修改运动规划器：当前快照的距离、前瞻、E/PA 语义必须单独验证。
MCU 继续执行定时步进；这次不改 MAX EZ / EBB36 固件。

算法包与版本相关适配层分离：

1. `rtcp_portable`：不导入 Klipper；配置/几何接口保持稳定。
2. 未来 `klipper_adapter`：绑定具体源码/接口版本，处理原生 UV、队列、坐标缓存及异常。
3. 每机配置：中心、符号、限位、标定来源。现场 `printer.cfg` 仍是驱动方向/齿比的权威配置。
4. 作业配准：本次视觉位移与 U/V 参考版本绑定，不作为永久硬件标定保存。

## 启停与“开断打印”

RTCP 的开关按**坐标语义/作业阶段**管理，不按 E 是否挤出来管理。
相邻路径之间停挤出、回抽、空走都不能简单关掉 RTCP。

| 阶段 | 期望状态/前提 |
|---|---|
| 回零、四 Z 调平、探测、重新建立 U/V 参考 | RTCP OFF；用机器坐标 |
| 视觉采集/配准 | 参考已建立；本版要求定义的床面零姿态 |
| 打印开始启用 | 完成上述准备，校验版本/标定/限位，运动队列到达确定边界 |
| 打印、空走、回抽 | 保持同一 RTCP 作业上下文 |
| 正常暂停 | 保留上下文；停车/抬头动作必须明确坐标系且进行安全规划 |
| 正常结束 | 在适当坐标系完成安全退让，确认队列完成，再无跳变关闭 |
| 取消 | 明确停止策略和最终状态，处理队列，关闭上下文；不能当普通结束 |
| 故障、重启、电机失能、未知位移 | 清除参考有效性；不自动停车或恢复打印 |

本包 `begin/end` 只改变解释方式而不改变模拟物理位置。
`pause()` 要求模拟队列已清空；实际暂停必须由接入层完成调度，不能直接照搬这个调用。
`cancel_after_stop_simulated()` 的确认只是测试输入，**不是检测到真实机器停止**。
`fault/reset` 清除的是内存模拟队列，**不能撤回 MCU 已收到的运动**。

接入时要同时更新/协调 G-code 位置、toolhead 位置、运动队列、U/V trapq 与参考状态。
只拦截 G1、只修改显示坐标、或调用一次 M400，都不构成完整的启停/取消实现。
G28、调平、G92、SET_GCODE_OFFSET、SET_U/V、FORCE_MOVE、手动移动和电机失能等入口
必须由真实适配层管控；目前 `guard_machine_operation` 仅证明期望行为，并未钩住这些命令。

## 本地快照发现的接入前问题

证据：`reports/snapshot-audit.json` 中的文件哈希和行号，另有人工检查。
这些不是实时机器状态，也不保证另一进程尚未修复：

- 快照 U 齿比是 60:16，与本次确认的 260:18 不一致。
- `SET_U/SET_V` 调 `SET_KINEMATIC_POSITION U/V`，但快照 `force_move.py`
  的解析只取 X/Y/Z，归零轴过滤也只接受 xyz。
- `RotaryAxis.set_reference()` 调用了快照 `toolhead.py` 未定义的
  `set_extra_axis_position()`；扫描范围内未找到 set_reference 调用者。
- 快照原生 UV 的 `check_move` 有参考/有限值/速度检查，但没有明确角度范围检查。
- `laser_motion.py` 仍依赖 manual_stepper 和缺失的 move_generation 接口；
  不能让旧功能未经隔离就接管新的运动。

自动审计是窄范围静态检查，不解析全部 include，不会执行下载的代码。
其“未找到”的启发式提示需要人工判断，不能当作适配层正确性的证明。

## 分段误差与限位边界

一段内模型点和 U/V 角度都线性插值。设：

```text
w(t) = 模型点(t) + 工件偏移
s = |ΔU弧度| + |ΔV弧度|
M = s² × max(|w0|, |w1|) + 2s × |w1-w0|
理想曲线到直线弦的距离 ≤ M/8
```

这是对 `Rx(U)Rz(V)w` 二阶导数的保守范数界，再使用线性插值误差界。
每次二分重新计算，不仅检查中点，因此多圈运动不会被“端点/中点重合”漏掉。
端点弦的 XYZ 包围盒向外各扩展此界，必须整体在配置行程内。
U/V 不自动跨 360°取最短路，按输入连续数值插值，线性轴限位由端点控制。

代价是可能保守拒绝：靠近边界但实际安全的路径也可能无法在指定深度内确认。
超限、无法确认或超出计算预算都拒绝整个待处理块，不部分提交。
计算使用普通浮点数，不是严格的区间算术或安全认证。
没有喷嘴/龙门/床盘/夹具碰撞模型；轴行程合规不等于无碰撞。
v1 输出只有几何点和误差界。v2 的速度/加速度检查只适用于给定合成/标定约束下的
离散折线与逐段停稳时间曲线，不能直接证明实机性能或打印质量。

## Open5x 下一阶段

需先取得一小段“导出前几何 + 实际导出 G-code”作对照，确认：

- XYZ 是模型/床面坐标，还是已经补偿过的机器坐标，避免二次补偿。
- A/C 是平台命令角、刀轴姿态角还是其他欧拉角；不是统一改成 U/V 就正确。
- 旧 A 算法若是 Ry，不能仅换名字来匹配本机 Rx。
- 单位、绝对/相对模式、角度连续展开、E 模式、F 定义、回抽/空走、起止宏。
- E 按原始沉积路径分配到子段，不能按补偿后的 XYZ 路长随意缩放。
- 旋转路径和喷嘴路径需在同一时间参数下规划，验证 TCP 进给、UV 速度/加速度、
  CoreXY 电机组合约束及压力提前策略。

在这些语义没有确认前，v1 几何格式仍拒绝 E/F 和旧 A/C 字段，不进行猜测转换。
v2 只接受新定义的模型坐标/平台角和显式进给事件，不把旧 G-code 自动解释成该格式。

## 上机顺序（需要另行协调）

1. 另一进程完成运动调试后，只读重新取版本/配置与源码哈希。
2. 修复/验证原生 UV 参考 API、角度限位和齿比；隔离旧 laser 路径。
3. 标定实际中心 XYZ、方向、零姿态、保守机械边界及高度；确认共点近似误差。
4. 完成版本化适配层与统一规划，先运行 host-only/mock 回归。
5. 人工确认可控窗口和安全姿态后，再做无料、低速、小角度实机测试。
6. 再测暂停/取消/故障、Open5x 作业，最后才进入挤出打印。

本轮没有执行以上任何实机步骤。
