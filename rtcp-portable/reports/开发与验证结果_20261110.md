## 已落实的关键设计

1. 与现场 CoreXY 电机映射分离，采用共点 Rx(U)Rz(V) 模型。
2. 机器中心 C 与工件偏移 d 分离，d 随床旋转；不重复补偿圆盘偏心。
3. U/V 正方向可配置，U260:18 作为机器参数保存，不重复乘进几何角度。
4. 使用物理 XYZ/UV 限位和保守误差界，不仅检查输入点或旋转端点。
5. 启停保持物理位置；队列非空拒绝切换；正常暂停保留作业上下文。
6. 重新设零、故障、电机失能后旧配准不可复用；新进程不继承已归零/ACTIVE 状态。
7. 机器配置缺失时拒绝运行，不把合成限位/中心当真实参数。
8. 软件、每机标定、每次工件配准分离，迁移说明及计划记录已保存。

## 审查发现的接入问题

以下针对**历史快照**，不宣称是当前运行状态，另一调试进程可能已处理：

- U 实际配置为 60:16，与确认值 260:18 不符。
- `SET_U/SET_V` 使用的 `SET_KINEMATIC_POSITION` 在对应源码中只解析 XYZ。
- 旋转参考设置方法依赖未定义的主机接口；所扫描文件中未发现它的调用者。
- 原生 UV 缺少明确角度范围检查。
- 旧激光路径依赖 manual_stepper / move_generation，与当前接口冲突。

自动审计共有 7 条提示，属于有限范围静态检查，不是完整配置或安全认证。
这些风险均未通过直接修改树莓派来处理。

## 离线上尚未解决的实机问题

本包不是现成打印插件。真实 Klipper 队列接入、XYZUV/E 统一进给与挤出规划、
压力提前、Open5x A/C 与坐标语义转换、实际宏启停钩子、机械碰撞验证仍未实现。
模拟 cancel/fault 只清内存状态，不能取消 MCU 已排队的动作。
也没有声称已读取 STEP 完成精确机械碰撞仿真。

下一阶段先确认现场配置版本，完成 UV 接口与标定，再开发/验证接入层。
需要另行协调实机窗口；不会在另一进程调试时自动安装或重启。

## 本轮工具问题

几何与状态测试未出现失败。安装验证的前两份报告仅有 Windows 中文路径显示乱码；
原因是隔离解释器忽略 Python 输出编码环境变量，后改为 ASCII 转义 JSON 传递，
最终 `portability-verified.json` 已正确保存中文路径。旧报告保留作记录，不作为分发证据。
在线官方文档工具未返回可用内容，兼容性结论使用本地版本化快照，而非猜测最新源码。
