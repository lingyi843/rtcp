## Decisions Made

| Decision | Reason |
|---|---|
| 沿用用户提供 PPT 的母版与版式 | 用户明确要求参考此前 PPT 格式。 |
| 使用“工作重点 + 人员分工 + 协同机制 + 行动计划”的结构 | 该结构直接服务于管理层对方向、责任和执行节奏的理解。 |
| 对缺失的人名、具体项目和指标采用可编辑占位信息 | 避免凭空捏造部门事实，同时使文件可直接完善。 |
| 将源文件复制到 ASCII 路径且 ASCII 文件名的临时目录后再检查 | 第一次副本仍位于中文工作区路径中，底层 unzip 仍无法读取；复制不影响原文件。 |
| 使用临时 unzip 兼容包装器完成只读模板审阅 | 当前环境没有 unzip 命令；包装器仅以 .NET ZipArchive 模拟脚本所需的 -Z1 / -p 读取接口，不修改 PPTX。 |
| 输出 9 页管理汇报 | 以封面、目录、部门定位、工作重点、成员分工、职责边界、协同机制、四周计划和结束页构成完整管理叙事。 |
| 成员姓名除张易外标注“待填” | 用户未提供成员名单，保留清晰可编辑的岗位责任框架，不虚构人员信息。 |
| 用对象名称而非重新导入后的锚点修改 starter deck | 保留继承元素的页面和对象名称稳定，而 artifact-tool 的对象锚点在再导入后会重新生成。 |
| 改用真实团队分工替代通用角色占位 | 用户已明确提供三位成员及长期职责，汇报必须反映实际落地组织。 |
| 以“设备调试—视觉激光定型—电路板推进”作为当前重点 | 这三条主线直接来自用户给出的部门当前工作目标。 |
| 以桌面文件作为 Phase 7 的唯一底稿并另存细化版 | 用户说明其已自行修改 PPT，必须保留这些最新改动，同时避免覆盖原文件。 |

## Errors Encountered

| Error | Attempt | Resolution |
|---|---:|---|
| 模板检查脚本无法通过 unzip 读取带中文路径的源 PPTX | 2 | 第一次副本仍含中文目录；改用 C:\\tmp 下完整 ASCII 路径的副本。 |
| 模板检查命令未启动 | 1 | 指定的 C:\\tmp 工作目录尚未创建；从已存在的 C:\\ 工作目录创建该临时目录后重试。 |
| 源 PPT 幻灯片拼图脚本以 Node 启动失败 | 1 | 该辅助脚本是 Python 文件；改用工作区提供的 Python 运行时执行。 |
| starter deck 映射校验未通过 | 1 | 默认模板检查文件受字符上限截断，缺少源第 19 页的两个文本框；改用已生成的完整对象检查文件进行校验。 |
| starter deck 联系表生成失败 | 1 | starter PPTX、预览和对象检查已生成；脚本仅在调用不可用的 python3 生成联系表时失败。改用捆绑 Python 工具单独生成拼图。 |
| 编辑脚本无法用导入前的对象锚点解析 starter deck | 1 | PPTX 再导入后对象锚点重新生成；改按已保留的页面序号与对象名称精确定位同一继承元素。 |
| 溢出检查脚本未取得 RUNTIME_NODE | 1 | 生成拼图命令未传入运行时变量；下一次将以完整三项运行时变量执行，避免重复相同环境错误。 |
| PowerShell 对象汇总命令出现空管道语法错误 | 1 | 将 `foreach` 结果先赋给变量，再单独传给 `Format-Table`，第二次执行成功。 |
| starter deck 映射校验要求所有复制的标题/副标题占位符必须显式处理 | 1 | 为保留页的标题/副标题加入同文 rewrite 映射，确保结构性占位符满足模板约束。 |
| 编辑脚本使用 `table.rows.length` / `table.columns.length` 判断导入表格尺寸时误判 | 1 | 移除不兼容的预检查，沿用已验证的 `table.cells.set(row, column, value)` 逐单元格写入方式。 |
